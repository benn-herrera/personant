# Within-thread summary hierarchy — the H1 structural fix (#109)

**Status:** design (a focused design pass preceding build, per SPEC §3.4 / the #109 hazard-H1
trip-wire). **Companion to** `ROADMAP_PLANS/intra-thread-recall-design.md` (authoritative for I1–I8,
F1–F6, coarse→fine §4, the shadow-chunk oracle §8, and AC1–AC6). This document resolves **only** the
engaged-thread intra-pass: it replaces the O(C_main) flat chunk scan with an O(log n) descent over
an LLM-summary tree built within one thread by the sleep cycle. Everything else in the #109 design
is unchanged and not re-litigated.

## 0. The problem this fixes (the measured trip-wire)

The shipped #109 engaged-thread intra-pass (`measure.Service.intraThread`) runs
`scoring.ProposeChunks` over **all** of `snap.fine[engaged]` — every retained chunk of the engaged
thread, uncapped. The 60-day perf rung measured this as exactly the linear decay the I3 no-decay bar
forbids:

| metric | 60d | 120d-projected | growth |
|---|---|---|---|
| `recall_query_cosine_ops` | 36M | 146M | 4× |
| `recall_index_fine_chunks_main` | 4286 | 17284 | 4× |

The coarse tier stayed flat (`coarse_size ≈ T`, population recall unaffected), so this is
**specifically the engaged long thread**: its fine-pass term in the §4.3 cost model is
`(Kc+1)·C_main·D`, linear in `C_main`. Hazard H1 in the #109 design flagged that "if a single
thread's `C` grows so large the engaged-thread fine pass becomes the latency floor, a per-thread
sub-index is warranted." That metric has now bent. This is the per-thread sub-index, scoped and
gated.

The fix has two coupled parts, designed coherently:
- **The hierarchy** is the *structural* fix — O(log n) per query instead of O(n).
- **PRNG keep/toss trimming** (the sim stand-in for the `lifetime:` marker) is a *constant-factor*
  win on the retained-leaf count (slope, not order). Trimming shrinks `n`; the hierarchy changes the
  exponent. Both land in the same sim perf rung so AC2 measures the trimmed case under the descent
  cost model.

## 1. Invariants

These hold regardless of implementation; they are the review exit contract. They **extend** I1–I8
(the #109 index invariants); the snapshot, the atomic-pointer swap, the watermark, and the
derived-cache invariants all still apply to the chunk vectors the tree's leaves point at.

- **W1 — Recall-preservation (the safety property; the headline).** The hierarchy is a **performance
  optimization that must not change which leaves are recalled.** For any query `q` and engaged
  thread, the top-Kf leaves returned by beam-descent must equal the top-Kf leaves the flat O(C_main)
  `ProposeChunks` scan would return, within a stated beam tolerance. Speed is never traded for
  recall. This invariant has a dedicated sim gate (§7); divergence beyond tolerance is a
  build-blocking failure, not a tuning note.
- **W2 — O(log n) per-query intra-pass.** The engaged-thread intra-pass cost is `O(k·B·log_B(n)·D)`
  where `n` is the engaged thread's retained-leaf count, `B` the branching factor, `k` the beam
  width — **not** `O(n·D)`. Per-query cost is bounded by tree *depth*, not thread *length*. A thread
  with 50 000 leaves costs `log_B` more than one with 50, not 1000×.
- **W3 — Beam, never greedy.** Descent keeps the top-`k` branches per level, not the top-1. A
  relevant leaf can sit under an intermediate node whose summary cosine-misses the query (a summary
  averages a heterogeneous cluster); greedy top-1 would prune that subtree and lose the leaf. Beam
  width `k > 1` is the recall-preservation mechanism (W1's *how*). Greedy top-1 descent is a
  review-reject.
- **W4 — Flat-thread invariant preserved (intra-thread graph ONLY).** The tree is a navigation
  structure **within one thread, over that thread's own retained leaves.** It is *never* a
  cross-thread structure: it introduces no parent edge between threads, no shared root, no
  thread-to-thread summary node. Threads stay parentless (the U7/DG-1 flat-thread model). One tree
  per indexed thread, rooted at that thread's leaves, referenced by `threadID` exactly as
  `snap.fine[threadID]` is today.
- **W5 — Derived, rebuildable, never canonical.** The whole tree — every summary node, every summary
  embedding, the topology — is **derived from the leaves** (the retained turn-excerpts, which are
  canonical per #109 §13). It is gitignored, staleness-keyed, and rebuilt-on-miss exactly like the
  Inc-3 vector cache. Deleting it costs LLM summarization + embedding CPU at next sleep cycle, never
  data. The summary *text* is a derived artifact, not a substrate body, and is never committed to
  git.
- **W6 — Built offline by the sleep cycle, never per-turn.** Summary nodes are generated by batched
  LLM calls during the consolidation pass (ARCHITECTURE "sleep cycle" / consolidated tier), on the
  idle window, off the turn's critical path. No turn ever waits on a summarization call. Per-turn
  the runtime touches only the *already-built* tree (descent) and marks dirty subtrees (§5); it
  never summarizes.
- **W7 — Bounded, amortized build cost.** Over a thread's life the total summarization LLM-call
  budget is `O(n / B)` per full build (one call per internal node), amortized `O(1) per leaf` across
  the thread's lifetime via incremental dirty-subtree reconcile (§5). A sleep pass re-summarizes
  only subtrees dirtied since the last pass, never the whole tree.
- **W8 — Graceful degradation to the flat scan.** When the tree for the engaged thread is absent,
  stale-beyond-use, or below the build threshold (a short thread), the intra-pass falls back to
  today's flat `ProposeChunks`. The tree is an optimization layered over a still-correct flat path;
  its absence costs speed on long threads, never correctness. This makes W5 (deletable) and the
  short-thread case free, and makes the build a pure win with no new failure surface on the recall
  path.

### 1.1 Failure modes the design must prevent (pre-output reasoning)

The skeleton below exists to block these specific coder paths. Each maps to the invariant that
prevents it.

| # | Likely wrong path | Prevented by |
|---|---|---|
| G1 | Greedy top-1 descent (keep only the best branch per level) — "simpler, one path down." Loses any leaf under a summary that cosine-misses. | **W3** + the §7 recall-preservation gate. Greedy descent fails the gate by construction on a wandering thread; it is a review-reject. |
| G2 | Summarize per-turn (build the tree on the turn loop, or rebuild on every scroll-out). Puts an LLM call on the critical path; blows the embed-call budget. | **W6/W7**. The builder lives in `Consolidate`, not the turn loop. The turn loop only marks dirty (§5). |
| G3 | Thread-hierarchy creep: reuse the tree type across threads, add a parent edge, build a shared root, or let a summary node span two threads. Violates the flat-thread model. | **W4** + the negative constraint on the tree package. One tree per thread, keyed by `threadID`; no cross-thread node exists in the type. |
| G4 | Treat the tree (or summary text) as canonical — commit it to git, or make recall depend on its presence. | **W5/W8**. Tree is gitignored derived state; recall falls back to the flat scan when it is absent. |
| G5 | Ship the speed win without gating recall — assume descent ≈ flat scan and move on. | **W1** + the §7 gate. The gate runs descent and flat scan over the same leaves on the same queries and fails on divergence beyond tolerance. No green AC2 without a green recall-preservation gate. |
| G6 | Full re-summarize every sleep pass (re-LLM the whole tree). O(n) calls per pass — untenable at multi-year scale. | **W7** + the dirty-subtree reconcile (§5). A pass re-summarizes only dirtied subtrees. |
| G7 | Build the tree over the *live FIFO window* leaves too (index in-context content). | I6 (inherited). The tree's leaf set is exactly `snap.fine[threadID]` — scrolled-out chunks only. The window is never a leaf. |
| G8 | Let the tree go stale silently — descend an outdated topology after leaves were trimmed/added, returning leaves that no longer exist or missing new ones. | **W5** staleness key (§6) + W8 fallback. A tree whose children-hash no longer matches the leaf set is stale → rebuild-subtree or fall back to flat until the next sleep pass reconciles it. |

## 2. The structure

### 2.1 What the tree is

A per-thread, multi-level tree over the thread's retained-leaf set:

- **Leaves** = the existing fine-tier chunk vectors, `snap.fine[threadID]` — one per retained
  scrolled-out turn-excerpt (#109 §3 / §13). **The tree adds no new leaf representation;** it points
  at the chunk vectors that already exist. This is the seam that keeps W1 cheap: the leaves descent
  returns are the identical `ChunkVector`s the flat scan ranks.
- **Internal nodes** = LLM-generated summaries of a group of children (leaves at level 1, lower
  summary nodes above). Each internal node carries:
  - `summary` — the LLM-generated text (derived, never committed; §5.2).
  - `vector` — the embedding of that summary text (the descent key).
  - `children` — node IDs / leaf turn-numbers (the topology).
  - `childrenHash` — staleness key = hash of the children's content hashes (§6).
- **Root** = the single top summary node for the thread.

Branching factor `B`, so depth ≈ `log_B(n)`. Query descends from root, keeping the top-`k` branches
per level by summary-vector cosine, until it reaches a leaf frontier of bounded size, then ranks
those leaves by their *leaf* (chunk) vectors — the same cosine the flat scan uses, which is what
makes the returned leaves comparable to the flat scan's (W1).

### 2.2 Why summaries, not just clustered raw chunks

A cheaper non-LLM alternative exists — cluster the chunk vectors (k-means / hierarchical
agglomerative) and use cluster *centroids* as the internal-node keys, no LLM. It was considered and
is recorded as a fork sub-option (§9, fork F-A). The summary-text approach is the design because:

- A centroid of a heterogeneous cluster is a meaningless point in embedding space; an LLM summary of
  "the API-redesign discussions" is a coherent unit the descent can match a topic query against —
  closer to the recall target than an average vector.
- The sleep cycle already has an LLM budget and an offline window (W6); the marginal cost of summary
  calls is amortized and off the hot path (W7).
- Summaries are independently *useful* — the consolidated tier (ARCHITECTURE) wants exactly
  "re-packed orderly arrangements" of fragmented history; a topic-summary tree is that artifact, not
  just an index accelerator.

The centroid path is the boring fallback if summary build cost proves unaffordable (§9 F-A); it is
not built v0.1.

## 3. Clustering strategy — the decision

**This is the prime contested fork. Decision: semantic clustering, with a recency tie-break — and a
flagged MAD on the semantic-vs-hybrid boundary (§9).**

The three candidates:

| strategy | groups leaves by | strength | weakness |
|---|---|---|---|
| **Recency-bucketing** | contiguous turn-number ranges | trivial build (no clustering pass); trivial incremental append (new leaves → new rightmost bucket); stable topology | a wandering multi-year thread scatters topic-X content across the whole timeline — a topic query must descend into *many* recency buckets to gather it, eroding the O(log n) win and the recall-preservation margin |
| **Semantic** | embedding similarity (group related leaves regardless of when) | matches the #109 target case exactly — topic-X content lands under one subtree even when scattered in time; tightest summaries; best recall-preservation margin per beam width | costlier build (a clustering pass over leaf vectors); rebalancing is non-trivial when new leaves arrive (a new topic may need a new subtree, or split an existing one) |
| **Hybrid** | recency at the top, semantic within recent windows | bounds the clustering cost to a window; bounds rebalancing churn | two mechanisms to maintain; the semantic benefit is capped at the window — a topic older than the window is recency-bucketed again |

**Why semantic is the call.** The motivating workload (#109 §9.1, Candidate A) is *deliberately* a
deep-trajectory thread whose early content is vocabulary-distinct and scattered — that is the
realistic intra-thread drift-recovery case the whole feature exists for. Recency-bucketing is
structurally mismatched to it: a topic query against a recency tree fans out across buckets, which
is the O(n) fan-out we are eliminating wearing a different hat. The user leans semantic for this
reason and the reasoning holds: group related leaves, regardless of time.

**The decision in detail (resolved, buildable):**

- **Clustering algorithm: agglomerative bottom-up over leaf vectors, capped fan-in `B`.** At build,
  cluster the leaf vectors into groups of ~`B` by cosine proximity (a single agglomerative pass with
  a `B`-cap, or balanced k-means with `k = ceil(n/B)`); summarize each group → level-1 internal
  nodes; repeat over the level-1 node vectors → level-2; up to the root. Bottom-up keeps the tree
  balanced and the depth at `log_B(n)`. The clustering itself is **deterministic given the leaf
  set** (fixed tie-break by turn-number) so a rebuild from the same leaves yields the same topology
  (W5 rebuildability + reproducible tests).
- **Recency tie-break, not recency structure.** When two candidate merges are near-equal in cosine,
  prefer the one that keeps temporally-adjacent leaves together. This gives semantically-coherent
  clusters a mild locality bias (adjacent turns are often the same sub-discussion) without making
  recency the organizing axis. It is a tie-break inside the semantic clusterer, not a separate
  recency level.
- **Rebalancing on incremental add (§5):** new leaves are assigned to the nearest existing level-1
  cluster by cosine; a cluster that exceeds `~2B` after adds is split (re-summarize the two halves);
  a level that exceeds its node budget triggers a one-level re-cluster of that level only. **Full
  re-clustering is a rare, sleep-cycle-only event** (e.g. when accumulated drift exceeds a
  threshold, or on explicit cache rebuild), never per-pass. This bounds rebalancing churn (W7) while
  keeping clusters semantically tight enough that the beam stays narrow (W1/W2).

**The flagged MAD (§9, F-B):** the *semantic-vs-hybrid* boundary at extreme depth is genuinely
uncertain — whether unbounded semantic rebalancing on a multi-year thread stays bounded, or whether
a hybrid recency-cap on the *top* levels is needed to bound rebalancing churn, is not resolvable
from first principles here. Recommended for a targeted MAD once the sim has a 120d+ rung with the
real rebalancing cost measured. v0.1 builds **semantic**; the metric (`recall_intra_
tree_rebuild_calls`, §7) is the trip-wire that escalates to the hybrid MAD.

## 4. The descent query (replaces the flat intra-pass)

`Service.intraThread` (today: flat `ProposeChunks` over all of `snap.fine[engaged]`) becomes a beam
descent over the engaged thread's tree:

```
descend(q, tree, B, k, Kf, leafFrontierCap):
    frontier := { tree.root }
    while frontier holds internal nodes:
        children := union of node.children for node in frontier
        // rank children (summary nodes OR leaves) by cosine(q, child.vector)
        frontier := top-k of children by cosine            // BEAM, not top-1 (W3)
    // frontier is now <= leafFrontierCap leaves
    leaves := the ChunkVectors for the frontier leaf turn-numbers
    return ProposeChunks(q, leaves, {Limit: Kf})           // SAME cosine as flat (W1)
```

- The terminal `ProposeChunks` over the leaf frontier is the **identical pure function** the flat
  scan uses — so the leaves descent returns are scored on the same operating point, and the only
  difference from the flat scan is *which leaves were considered*. W1 is then exactly: "the beam
  reached the leaves the flat scan would have ranked top-Kf."
- **Fallback (W8):** if `tree == nil` or `tree.stale` (children-hash mismatch beyond a tolerance) or
  `n < treeBuildThreshold`, skip descent and run the flat `ProposeChunks` over all of
  `snap.fine[engaged]` — today's code, unchanged.
- The engaged-thread bypass-the-coarse-gate semantics (#109 §4.1 step 3) are unchanged: the tree
  replaces *only* the inner fine scan over the engaged thread's chunks; the population coarse→fine
  path (§4.1 steps 1–2) is **not touched** (the clean seam, decided constraint 6).

### 4.1 Knobs: B, depth, k, frontier cap — starting values + cost model

| knob | start | rationale |
|---|---|---|
| `B` (branching factor / fan-in) | **16** | depth `log_16(n)`: 10⁴ leaves → depth 4; 10⁵ → depth 5. Wide enough that depth stays tiny; narrow enough that a level's beam-rank over `k·B` children is cheap. A §9-calibration window. |
| `k` (beam width) | **4** | top-4 branches per level. The recall-preservation knob (W3): wider `k` recovers more leaves under cosine-missing summaries, at linear descent cost. Start at 4; the §7 gate *raises* it if recall diverges, *lowers* it (toward the flat scan's behavior) only if the margin is large. **`k` is tuned by the recall-preservation gate, not by latency.** |
| depth | derived `≈ log_B(n)` | not a free knob; falls out of `B` and `n`. |
| `leafFrontierCap` | **`k · B`** | the leaf set the terminal `ProposeChunks` ranks — bounded by beam, independent of `n`. |
| `treeBuildThreshold` | **`2·B` leaves** (≈32) | below this, a flat scan is already cheap and a tree is pure overhead; W8 fallback handles it. |

**Per-query cost model (W2):**

```
descent cost = depth · (k · B) · D            // beam-rank k·B children per level, log_B(n) levels
            = O(k · B · log_B(n) · D)
plus leaf rank = leafFrontierCap · D = O(k·B·D)   // terminal ProposeChunks, n-independent
```

Contrast the shipped flat term `O(C_main · D) = O(n·D)`. With `B=16, k=4`, `n=17284` (the projected
120d value): flat = ~17k·D leaf cosines for the engaged thread; descent = `4·(4·16)·D` per level ×
~4 levels ≈ `1024·D` + a `64·D` leaf rank ≈ **~1.1k·D**, a ~16× reduction at that `n`, and the gap
*widens* with `n` (constant vs. log). The total per-query model the sim must validate becomes:

```
recall_query_cosine_ops = T·D                       // coarse pass (unchanged, flat in T)
                        + Kc·C̄·D                     // population fine pass (unchanged)
                        + k·B·log_B(n_main)·D         // engaged-thread DESCENT (was Kf·C_main·D)
```

The engaged term is now **logarithmic in `n_main`, not linear** — the §0 decay is removed. This is
the new `modeledCosineOps` formula (§7).

## 5. Incremental build, rebalancing, staleness — the sleep-cycle builder

The builder runs inside the consolidation pass (`MemoryOps.Consolidate` / `Service.SweepCache`'s
sleep-cycle sibling), not the turn loop (W6). It is **incremental and dirty-driven** (W7):

### 5.1 Dirty-tracking (per-turn, cheap, no LLM)

- When a thread's leaf set changes — a leaf is **added** (a chunk scrolled out and was embedded into
  the fine tier; the existing debt/dormancy flush) or **trimmed** (keep/toss removes a leaf; §8) —
  the runtime marks the affected leaf and its ancestor path **dirty** in the tree's sidecar
  metadata. This is a cheap bookkeeping mark (set a flag / append a dirty turn-number), **no
  summarization**.
- Dirty marks accumulate between sleep passes. The fine-tier swap point (where the indexer already
  publishes new chunk vectors, #109 §6.3) is the natural place to also append the dirty marks for
  the new leaves.

### 5.2 Reconcile (sleep pass, batched LLM)

On a consolidation pass, for each thread with dirty marks:

1. **Assign new leaves** to nearest level-1 clusters by cosine (§3); collect the set of internal
   nodes whose children changed (dirtied subtrees).
2. **Split overflowing clusters** (`>~2B`) and **merge underflowing** ones, bottom-up, touching only
   the dirtied path.
3. **Re-summarize only the dirtied internal nodes** — one batched LLM call per dirtied node
   (children text → summary text), then embed the new summary text. A node whose children are
   unchanged keeps its cached summary + vector (the children-hash matches, §6) — **zero LLM calls
   for the clean majority** of a large tree.
4. **Persist** the updated nodes to the derived cache (§6) and clear the dirty marks.

Total LLM calls per pass = number of dirtied internal nodes ≈ `O(Δleaves / B)`, not `O(n)` (W7, G6).
Over the thread's life this amortizes to `O(1) per leaf` — each leaf participates in `~log_B`
summarizations across the levels it is under, and each summarization is shared across `~B` siblings.

### 5.3 Composition with #108's existing Consolidate (gc)

The hierarchy build runs **in the same sleep pass** as the existing day-off `Consolidate` (git gc /
repack / archival, ARCHITECTURE sleep cycle). The pass gains a step: after the existing cache
`Sweep` (drop `.vec` for archived threads), run the tree reconcile for dirtied live threads.
Ordering: leaf-tier reconcile (#109 Reconcile) **before** tree reconcile, so the tree summarizes a
settled leaf set. The build is opportunistic and non-fatal (like `SweepCache`): a failed
summarization leaves the prior tree in place; descent falls back to flat (W8) until the next pass
succeeds. **No turn waits on it.**

**Full-rebuild cost (cache deleted / W5):** one pass over all leaves — `O(n/B)` LLM calls for the
whole thread, the amortized budget paid in one go. For a multi-year thread this is large but
offline, batched, and rare (only on explicit cache loss). The `recall_intra_tree_summary_calls`
metric (§7) bounds it.

## 6. Derived-cache integration

**Extend `measure/veccache` (the Inc-3 cache), not a sibling.** The tree is the same *kind* of
artifact the `.vec` cache already is — derived, gitignored, staleness-keyed, per-thread — and it
sits beside the chunk vectors it indexes.

- **Layout:** add a per-thread tree file beside the existing `.vec`:
  `.recall-cache/threads/thr_<id>.tree` (JSON v0.1, same D-B reasoning as `.vec`: derived, not
  human-edited; binary only if measured to warrant it). It holds the topology + per-node `{summary,
  vector, childrenHash}`. The leaf vectors stay in `.vec` (single source of truth, DRY — the tree
  references leaves by turn-number, never copies their vectors).
- **Staleness key for a summary node = `childrenHash`** = hash of the ordered content-hashes of its
  children (for a level-1 node, its leaf chunk-hashes — which `.vec` already stores; for higher
  nodes, its child nodes' `childrenHash`es). This composes the existing per-chunk `chunk_hash`
  staleness up the tree: a leaf change re-hashes exactly its ancestor path, which is precisely the
  dirtied set (§5). **No new hash function** — reuse `contentHash` and compose (DRY).
- **Reconcile** (startup / sleep) loads the tree, recomputes each node's `childrenHash` from the
  current leaf hashes, and marks mismatched nodes for re-summarization — the same content-hash
  rebuild-on-miss the `.vec` cache uses (#109 §5.3). A node whose `childrenHash` matches loads
  verbatim (zero LLM).
- **Sweep** drops `.tree` alongside `.vec` for archived threads (one more file in the existing
  `Sweep` loop).

The tree cache is **never canonical** (W5): the same I5 discipline — deletable, rebuildable from the
canonical leaves, never written into the git tree.

## 7. Gates: recall-preservation + no-decay, made measurable

### 7.1 The recall-preservation gate (the safety property, W1)

**The non-negotiable gate.** Run, on the Candidate-A workload, for every intra-thread probe query
`q` against the engaged thread:

- `flatTopKf(q)` = today's flat `ProposeChunks` over all of `snap.fine[engaged]`.
- `descentTopKf(q)` = the beam descent (§4) over the same leaves.

Metric **`recall_intra_descent_divergence`** = the fraction of probes where the descent's top-Kf
leaf set differs from the flat scan's top-Kf (set difference, not ordering). **Gate: divergence ==
0** within the beam (i.e. `k` chosen so the descent recovers every leaf the flat scan would). A
nonzero divergence is the zero-tolerance stop-and-root-cause signal (per the unexplained-absence
discipline): either raise `k` until it is zero, or — if a structurally unreachable leaf is found —
that is a clustering/topology bug, fixed on the build side, never by widening the gate's tolerance.
This gate runs on **every** sim run (it is a pure runtime-vs-runtime comparison,
embedder-independent in shape; on a live-embedding run it uses real vectors, on a mock run it uses
the mock embedder's vectors — both must agree descent==flat).

Because descent and flat both consume the same in-memory leaf vectors, this gate is **independent of
the oracle** — it does not ask "is the recalled leaf the right one" (that is the §8 shadow-chunk
oracle's job, unchanged); it asks only "does the fast path return the same leaves as the slow path."
That separation is deliberate: recall *quality* is the #109 oracle's gate (AC1); recall
*preservation* under the optimization is this gate. A green AC2 requires both.

### 7.2 The no-decay gates (W2, the I3 obligation)

Extend the §9.2 perf series:

- **`recall_query_cosine_ops`** — the new formula (§4.1): coarse `T·D` + population `Kc·C̄·D` +
  engaged **`k·B·log_B(n_main)·D`**. The `modeledCosineOps` change is the headline structural fix:
  the engaged term is now logarithmic in `n_main`. **Gate: `cosine_ops` grows only with `T` and
  `log(n_main)`, flat-to-log in main-thread length** — not the 4×-tracking-`fine_chunks_main` decay
  of §0.
- **`recall_query_latency_p99`** — flat across the 15d→30d→60d→120d ladder (the unchanged I3
  headline gate); now expected flat because the engaged term is log-bounded.
- **`recall_intra_tree_summary_calls`** — LLM summarization calls per sleep pass (W7 build budget);
  gate: **amortized `O(Δleaves/B)` per pass, not `O(n)`** — flat per-pass given a steady leaf-add
  rate, never tracking total `n`.
- **`recall_intra_tree_rebuild_calls`** — full/level re-cluster events (§3 rebalancing); the
  trip-wire for the F-B hybrid MAD: if this trends up with `n_main` on the 120d rung, semantic
  rebalancing is not staying bounded → escalate.
- **`recall_intra_tree_depth`** / **`recall_intra_tree_nodes`** — observed depth (must be `≈
  log_B(n_main)`) and node count (`≈ n_main/(B-1)`), the structural health check.

### 7.3 The keep/toss trim (PRNG model) and its effect

The sim's PRNG keep/toss model (decided constraint 7) is the deterministic stand-in for the
production `lifetime:` marker (SPEC §3.10.8): a fixed-seed PRNG that, per scrolled-out leaf, marks
it transient with probability driven by two tunable rate fields — `convoTransientRate` (start
**60%**) and `toolTransientRate` (start **75%**), the §9 calibration starting values. A transient
leaf is **trimmed** from the retained set (not embedded into the fine tier; if already embedded,
dropped on the next reconcile, dirtying its ancestor path per §5). This:

- shrinks `n_main` by a constant factor (the slope win) **before** the hierarchy applies its log win
  — so the perf rung measures the realistic *trimmed* case, not the over-retain worst case;
- is deterministic (fixed seed, part of the canonical stream — no rng drift, the determinism
  contract holds);
- must compose cleanly with the recall-preservation gate: a trimmed leaf is gone from **both** the
  flat scan and the descent (the gate compares the two over the *same* retained set), so trimming
  never *causes* divergence — it only changes `n`. The gate stays meaningful under trimming.

**Trimming is a constant-factor win on slope; the hierarchy is the O(log n) structural fix.** The
doc designs them coherently (decided constraint 7): both feed the same `recall_query_cosine_ops` /
`latency_p99` rung, and the gate (§7.1) holds with or without trimming.

## 8. The sim oracle — stays leaf-level (confirmed)

**Confirmed: the shadow-chunk oracle (#109 §8) stays leaf-level and is unchanged.** The hierarchy is
a runtime-perf-only structure; it changes *how* the runtime finds a leaf, never *which* leaf is the
ground-truth answer.

- The oracle still predicts, per intra-thread probe, **which leaf (turn-excerpt)** should be
  recalled — from the generator's own `shadowChunks` shadow, scored by `simJaccard` at
  `simRecallThreshold`, with the debt-window blind spot and the scrolled-out predicate exactly
  as #109 §8.2 defines them (F6: never a runtime index read).
- The runtime must **find that leaf via descent**. The AC1 coherence gate is unchanged:
  predicted-hit vs. observed `spine.intra-match-fire`, hop-bucketed, zero divergence.
- The §7.1 recall-preservation gate is the **new** layer between the oracle and the descent: it
  guarantees descent returns the same leaves the flat scan would, so the oracle's existing
  leaf-level prediction is automatically the right ground truth for the descent path too. The oracle
  does not need to know the tree exists. This is the clean separation: **oracle = is it the right
  leaf (quality, AC1); preservation gate = does the fast path find the leaf the slow path would
  (safety, W1).**

No oracle extension is needed beyond the new runtime-vs-runtime divergence metric (§7.1), which is
*not* an oracle (no ground truth, no shadow) — it is a differential test of two runtime code paths.
This keeps the oracle's symbolic shadow the cheap coherence gate and inherits #109's H2 closure
(the #98 embedding-in-loop run is the real quality validation), unchanged.

## 9. Module skeleton

Dependency direction unchanged from #109: `scoring` is substrate-free pure math; `measure` is
substrate-aware composition + owns the snapshot/cache/tree; `turn` drives the chain and owns the
dirty-mark + keep/toss hooks; `scenarios/sim` owns the oracle, the perf model, and the gates. **No
new package imports the substrate.** The summary LLM call goes through the existing chat-model
interface `measure` already holds for embedding (a summarizer is a `model.Chat`-style port, injected
like the embedder — nil → no tree, flat-scan fallback, W8).

### 9.1 `internal/recall/scoring/` (pure)

- **New `descend(query []float64, tree, B, k, Kf int) []ChunkCandidate`** — the pure beam-descent
  over a topology of `{vector, children}` + leaf `ChunkVector`s. Reuses `cosineSimilarity` and the
  terminal `ProposeChunks`. **Beam, not greedy (W3).** Pure: no I/O, no LLM, no substrate.
- **New tree types** if the topology is pure-data: `SummaryNode{Vector []float64; Children []int /*
  node or leaf refs */}` and the tree container. Or — if `measure` keeps the topology private
  (mirroring how the snapshot is private to `measure`) — `descend` takes an interface/accessor and
  the concrete tree lives in `measure`. **Decide at build time; default to the topology living in
  `measure`** (the snapshot is already private there; the tree is the same kind of private index
  state, and keeping it there avoids exporting the node type).
- **Negative constraint:** `scoring` knows nothing of summaries-as-text, the LLM, the cache,
  dormancy, or the FIFO. It is cosine math over a topology of vectors.

### 9.2 `internal/recall/measure/` (the tree owner)

- **New tree type** (private, like `indexSnapshot`): per-thread topology of summary nodes + their
  vectors, referencing leaf chunk vectors by turn-number. Held in / beside the `indexSnapshot` (e.g.
  `trees map[string]*summaryTree`), swapped atomically with the snapshot (same I1 discipline — the
  tree is part of the immutable published index).
- **`Service.intraThread`** changes from flat `ProposeChunks` to: descend the engaged thread's tree
  if present+fresh+above-threshold; **else flat-scan fallback** (W8). The *only* function that
  changes on the recall hot path.
- **New `summarizer model.Chat` field** (nil → no tree build, flat fallback). The builder uses it
  for §5.2 summary calls. Injected at construction beside the embedder.
- **New tree builder** (`buildTrees` / `reconcileTrees(ctx)`) called from the sleep-cycle entry
  (§5.2/§9.3), **not** from `Recall` or the indexer's per-job path. Batched LLM summary calls;
  writes nodes to the cache.
- **Dirty marks:** a per-thread dirty-turn set on the snapshot/cache, appended at the indexer swap
  point (new leaf) and at the keep/toss trim point (removed leaf).
- **Negative constraint:** `measure` does not put a summary call on the turn's critical path (W6);
  the descent reads only already-built nodes. The builder is sleep-cycle-only.

### 9.3 sleep-cycle entry (where the build hangs)

- The build is triggered from the **same owner that calls `Consolidate` / `SweepCache`** today (#108
  day-off). Add `Service.ReconcileTrees(ctx) error` beside `SweepCache` (the cache is operational
  state the adapter's `Consolidate` cannot reach — same seam reasoning as `SweepCache`). The owner
  calls, in order on a sleep pass: leaf-tier reconcile (existing) → `SweepCache` (existing) →
  `ReconcileTrees` (new). Best-effort, non-fatal (W8).
- **Negative constraint:** no new port method, no new canonical op (the tree is derived, like the
  `.vec` cache — not a port concept).

### 9.4 `internal/turn/` (the keep/toss + dirty hooks — no recall logic)

- At the keep/toss decision point (production: the `lifetime:` marker; §3.10.8), a trimmed leaf
  signals the recaller to drop it from the fine tier and mark its ancestor path dirty. v0.1
  production over-retains (#109 §13: retain all), so the keep/toss *trim* is **first exercised in
  the sim** (PRNG model); the production hook is the `lifetime:`-marker seam, stubbed to retain-all
  until §3.10.8 lands. **Negative constraint:** `turn` does not summarize, descend, or know the tree
  — it only signals "this leaf is gone / this leaf is new."

### 9.5 `internal/recall/measure/veccache.go` (cache extension)

- Add `.tree` file load/write/sweep beside `.vec` (§6); compose `childrenHash` from the existing
  `chunk_hash`es (DRY — no new hash). `Reconcile` returns the dirtied-node set for the builder.
- **Negative constraint:** the cache never writes the tree into git; never claims canonical (W5/I5).

### 9.6 `internal/scenarios/sim/` (the gate + the model + the PRNG trim)

- **`recall_intra_descent_divergence`** (§7.1) — the recall-preservation gate: run flat-scan and
  descent over the same engaged-thread leaves on each intra-thread probe; tally set-difference.
  Gate == 0.
- **PRNG keep/toss model** (§7.3): fixed-seed transient marking with `convoTransientRate` /
  `toolTransientRate` fields on the workload config; trim transient leaves from the retained set the
  perf model and gate see.
- **`modeledCosineOps` update** (§4.1 / §7.2): the engaged term becomes `k·B·log_B(n_main)·D` (was
  `Kf·C_main·D`); add the tree-build metrics.
- **Negative constraint:** the divergence gate compares two **runtime** paths; it is not an oracle
  (no shadow). The oracle (§8) is unchanged and still scores the generator's own shadow (F6).

## 10. Acceptance criteria

These **add to** #109's AC1–AC6 (all still hold). When this fix is complete:

- **WA1 — Recall preserved.** `recall_intra_descent_divergence == 0` on the Candidate-A workload
  across the rung ladder (descent returns the same top-Kf leaves the flat scan would). This is the
  load-bearing safety gate; no other AC is green without it.
- **WA2 — Decay removed.** `recall_query_cosine_ops` for the engaged term grows **logarithmically**
  in `n_main` (was linear, §0); `recall_query_latency_p99` flat across 15d→30d→60d→120d and
  flat-to-log in main-thread length — the §0 4× decay is gone. Cross-checked against the new model
  formula (§4.1).
- **WA3 — Build cost amortized + offline.** `recall_intra_tree_summary_calls` per sleep pass is
  `O(Δleaves/B)`, not `O(n)`; no summary call on the turn critical path (W6, verifiable by
  construction — `intraThread` calls no `model.Chat`); the build runs in the existing #108 sleep
  pass.
- **WA4 — Tree is derived.** Deleting `.recall-cache/*.tree` and running a sleep pass rebuilds an
  equivalent tree from the leaves; recall output (the leaves returned) is unchanged before and
  after, because the flat-scan fallback (W8) serves identical leaves while the tree is absent.
  (Equivalent topology, not byte-identical — clustering is deterministic given leaves, but the gate
  that matters is WA1, not topology identity.)
- **WA5 — Flat-thread preserved.** No tree node spans two threads; no parent edge between threads
  exists in the type (W4, verifiable by construction — the tree is keyed by a single `threadID` and
  its leaves are that thread's chunks only).
- **WA6 — Graceful degradation.** With no summarizer configured, or a short thread (`n <
  treeBuildThreshold`), or a deleted tree, intra-thread recall still works via the flat scan —
  correctness independent of the tree's presence (W8).

## 11. Hazards / forks

- **F-A (clustering mechanism — LLM-summary vs. centroid; LOW, decided).** Summary-text internal
  nodes (§2.2) vs. non-LLM cluster centroids. **Decision: LLM summaries** (coherent topic units,
  amortized offline cost, independently useful as the consolidated tier). Centroid is the boring
  fallback if summary build cost proves unaffordable on the 120d rung
  (`recall_intra_tree_summary_calls` the trip-wire). Recorded, not escalated — the decision is
  clear; the fallback is a measured-later contingency, not built.
- **F-B (clustering STRATEGY at depth — semantic vs. hybrid; MEDIUM, FLAGGED FOR MAD).** The §3
  decision is **semantic** for v0.1, on solid first-principles grounds (recency-bucketing is
  structurally mismatched to the scattered-topic target). The genuinely open question is whether
  **unbounded semantic rebalancing stays bounded on a multi-year thread**, or whether a hybrid
  recency-cap on the top levels is needed to bound rebalance churn. This is not resolvable from
  first principles — it depends on the measured rebalance rate at 120d+ scale. **Recommended for a
  targeted MAD** once `recall_intra_tree_rebuild_ calls` has a real 120d trajectory. v0.1 builds
  semantic; the metric escalates if it trends with `n_main`. **This is the prime MAD candidate.**
- **F-C (summary quality vs. recall-preservation; MEDIUM, gated not flagged).** A *bad* summary (the
  LLM mis-summarizes a cluster) produces a summary vector that cosine-misses queries its leaves
  should match — exactly what beam width `k` exists to tolerate (W3). The §7.1 gate catches this: if
  a real cluster's leaves are unreachable within beam `k`, divergence is nonzero → raise `k` or fix
  the summarizer prompt. So summary quality is **bounded by the gate**, not an unmonitored risk. Not
  a fork — the gate is the control. Flagged so a coder does not treat a nonzero divergence as "tune
  the threshold" rather than "the beam or the summary is wrong."
- **F-D (tree-build LLM budget on full rebuild; LOW).** A cache-loss full rebuild of a multi-year
  thread is `O(n/B)` summary calls in one pass — large but offline, batched, rare (W5/§5.3). If even
  the amortized incremental per-pass budget proves too high (a very high leaf-add rate on the main
  thread), the §9-calibration levers are `B` (wider → fewer nodes → fewer calls) and the keep/toss
  rates (more trimming → fewer leaves). Decided by measurement, not upfront.

**No scratch-rewrite fork.** The fix slots cleanly into the #109 boundary: it changes one hot-path
function (`intraThread`), adds one offline builder, extends the existing cache with one file type,
and adds one runtime-vs-runtime gate. The snapshot/atomic/watermark/oracle machinery is reused
unchanged. I did not find an approach within the decided constraints that cannot be made to work, so
I am not escalating a redesign. The one item I want a reviewer's eye on is **F-B** (the
semantic-vs-hybrid rebalancing-at-depth boundary) — it is the prime targeted-MAD candidate, and the
place a wrong call would let semantic rebalancing churn silently erode the W7 build budget on a
multi-year thread.
