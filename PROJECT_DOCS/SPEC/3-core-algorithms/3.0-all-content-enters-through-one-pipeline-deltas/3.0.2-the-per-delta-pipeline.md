#### 3.0.2 The per-delta pipeline

Each delta runs the pipeline, in this order:

1. **Symbol extraction** ([§3.3](../3.3-symbol-extraction-two-passes/index.md)) — identifier symbols and hashtags are extracted from the delta and
   the model's topic-tag symbols are read; where they land depends on the delta's retention class
   ([§3.10](../3.10-transient-data-lifecycle/index.md)).
2. **Engagement signal** ([§3.2](../3.2-topic-tagging-and-engagement-update/index.md)) — fire engagement for the threads the turn engages ([§3.2](../3.2-topic-tagging-and-engagement-update/index.md): those
   its topic tag names), coalesced per turn ([§3.0.4](3.0.4-turn-boundaries-and-per-turn-engagement-coalescing.md)).
3. **Dedup decision** ([§3.9](../3.9-working-set-content-dedup/index.md)) — the delta's file content is recorded once for the turn; which
   positions render content is decided at composition ([§3.9.2](../3.9-working-set-content-dedup/3.9.2-live-context-composition-working-window.md)).
4. **Budget check** ([§3.1](../3.1-working-set-composition/index.md)) — a delta that pushes the window over its slot caps triggers
   budget demotion before the next delta lands.

   > **v0.1 non-goal (turn-time budget enforcement).** This step performs no budget demotion in v0.1. The
   > only budget protections are (a) the per-thread recent-excerpt window ([§2.3](../../2-data-model/2.3-thread-file-format-threads-thr-id.md)) and (b)
   > render-time byte truncation of each slot ([§3.1](../3.1-working-set-composition/index.md)); neither acts at delta time, so an LLM whose
   > per-turn deltas outrun the slot caps can silently starve the active-threads and
   > dormant-threads slots. Enabling enforcement here is a separate decision, not an incremental
   > fill-in.
5. **Logging** ([§2.8](../../2-data-model/2.8-log-event-format-logs-yyyy-mm-dd-log/index.md)) — emit the source-specific event (`tool.result`, `user.shell-capture`, etc.)
   plus a `context.modified` event if the delta materially changed window contents.

The pipeline runs at **semantic boundaries** — complete response segment, complete tool result,
complete capture — not per token. A streamed response runs the pipeline on stream completion (or on
logical sub-segment boundaries).
