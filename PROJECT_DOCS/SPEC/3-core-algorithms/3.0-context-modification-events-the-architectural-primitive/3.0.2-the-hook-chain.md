#### 3.0.2 The hook chain

Each context-modification event runs the chain, in this order:

1. **Symbol extraction** ([§3.3](../3.3-symbol-extraction-three-passes/index.md)) — deterministic regex pass over the delta's content extracts
   identifiers (file paths, URLs, claim IDs, user `#`-tags); model-emitted symbols (in `topic`
   blocks) are parsed here too. Routing by the delta's retention class ([§3.10.1](../3.10-transient-data-lifecycle/3.10.1-provisional-classification-at-delta-time.md)) follows
   immediately: decision-class extractions go to the per-turn coalesce buffer; task-class
   extractions enter the staging buffer ([§3.10.2](../3.10-transient-data-lifecycle/3.10.2-staging-buffer.md)).
2. **Engagement signal** ([§3.2](../3.2-topic-tagging-and-engagement-update/index.md)) — if the delta's symbol set overlaps any active thread's anchors
   above threshold, fire engagement for those threads, coalesced per turn ([§3.0.4](3.0.4-per-turn-coalescing-for-engagement.md)).
3. **Dedup decision** ([§3.9](../3.9-working-set-content-dedup/index.md)) — a file-edit delta is buffered for the turn; at turn close it
   becomes an identifier line in the owner's excerpt and updates the tracked-file store
   ([§3.9.1](../3.9-working-set-content-dedup/3.9.1-persistent-storage-and-retention.md)). Which positions render content is decided at composition ([§3.9.2](../3.9-working-set-content-dedup/3.9.2-live-context-composition-working-window.md)).
4. **Budget check** ([§3.1](../3.1-working-set-composition/index.md)) — a delta that pushes the window over its layer caps triggers
   bump-eviction before the next event lands.

   > **v0.1 non-goal (turn-time budget enforcement).** This step performs no eviction in v0.1. The
   > only budget protections are (a) the per-thread turn-excerpt assembly window ([§2.3](../../2-data-model/2.3-thread-file-format-threads-thr-id.md)) and (b)
   > render-time byte truncation of each layer ([§3.1](../3.1-working-set-composition/index.md)); neither acts at delta time, so an LLM whose
   > per-turn deltas outrun the layer caps can silently starve Layer B/C. Enabling enforcement here
   > is a separate decision, not an incremental fill-in.
5. **Logging** ([§2.8](../../2-data-model/2.8-log-event-format-logs-yyyy-mm-dd-log/index.md)) — emit the source-specific event (`tool.result`, `user.shell-capture`, etc.)
   plus a `context.modified` event if the delta materially changed window contents.

The chain runs at **semantic boundaries** — complete response segment, complete tool result,
complete capture — not per token. A streamed response fires hooks on stream completion (or on
logical sub-segment boundaries).
