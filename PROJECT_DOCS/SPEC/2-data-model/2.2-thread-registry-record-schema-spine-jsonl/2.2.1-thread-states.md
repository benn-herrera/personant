#### 2.2.1 Thread states

A thread is in exactly one of these states:

- `active` — currently **engaged** (named by a turn's **topic tag**, the
  line that opens each model response and names the threads the turn engages, [§5.1](../../5-model-interaction/5.1-topic-tag-emission-format/index.md), or bound as its owner by the [§3.3](../../3-core-algorithms/3.3-symbol-extraction-two-passes/index.md) fallback; [§3.2](../../3-core-algorithms/3.2-topic-tagging-and-engagement-update/index.md)) or recently
  active (within the engagement decay window, `engagement.decay-turns` / `engagement.decay-time`,
  [§2.6.1](../2.6-directive-file-format-directives-md/2.6.1-recognized-parameters.md))
- `paused` — the user explicitly paused it
- `blocked` — gated on external input; user-confirmed
- `wip` — long-running with progress; not yet resolved
- `resolved` — problem solved; work complete
- `decided` — architectural decision recorded; no further action expected
- `abandoned` — explicitly dropped without resolution

`paused`, `blocked`, `decided` and `abandoned` stay readable for stored threads and are never
entered.

**State transitions** (see [§3.5](../../3-core-algorithms/3.5-closing-a-thread/index.md) for detailed flow):

| From | To | Trigger |
|---|---|---|
| (none) | `active` | thread creation |
| `active` | `resolved` | engagement decay ([§3.5](../../3-core-algorithms/3.5-closing-a-thread/index.md)) |
| (archived) | `wip` | archive restore ([§3.8.3](../../3-core-algorithms/3.8-cold-storage/3.8.3-restore.md)) |
| `wip` / `resolved` / `decided` / `abandoned` / `paused` | `active` | re-engagement (model emits topic tag) |
