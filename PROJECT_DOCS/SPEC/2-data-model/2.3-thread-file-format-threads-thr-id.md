### 2.3 Thread file format (`threads/thr_<id>/`)

Unused → ARCHITECTURE.md «Storage and record formats». A thread is a directory holding its
metadata (YAML frontmatter, canonical), one terse excerpt file per primary-engagement turn and the
[§3.9](../3-core-algorithms/3.9-working-set-content-dedup/index.md) tracked-file sidecar. Appending a turn writes one small file, so per-turn write cost does not
grow with thread length.

- Excerpts are decision-class content only: raw task-class output is never written as one
  ([§3.10.6](../3-core-algorithms/3.10-transient-data-lifecycle/3.10.6-what-stays-transient.md)). They are retained past the working-set assembly window, remain recall-indexed, and are
  the durable source of intra-thread recall ([§3.4](../3-core-algorithms/3.4-recall-matching/index.md)). Retention trimming is the deferred keep/toss
  layer ([§3.10.8](../3-core-algorithms/3.10-transient-data-lifecycle/3.10.8-content-retention-keep-toss-deferred-precision-layer.md)); v0.1 keeps all excerpts.
- Durable turn content lives only in excerpts, never the event log ([§2.8](2.8-log-event-format-logs-yyyy-mm-dd-log/index.md)).
- `description` is set deterministically at creation (a whitespace-collapsed copy of the spawning
  prompt, truncated; no LLM paraphrase) and never rewritten; a live thread has no `summary`.
- A thread has no parent-thread field and none is synthesized (the flat model, [§3.2](../3-core-algorithms/3.2-topic-tagging-and-engagement-update/index.md)); origin
  provenance is recorded per symbol (`derived_from`, [§2.7.3](2.7-symbol-normalization-and-categories/2.7.3-source.md)).
- A thread's symbol history is hard-capped at `history.cap-per-thread` (default 40) over active and
  superseded entries. Capacity eviction never removes a symbol that was once central or that is a
  high-specificity identifier while the protected set fits the cap; if the protected set alone
  exceeds it, the least-counted superseded entries go first.
