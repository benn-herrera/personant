#### 2.5.1 Authoritative: `projects/prj_<n>/meta.json`

Format → ARCHITECTURE «Storage and record formats» (the metadata layout). The store records, for
each project, two levels of identity (see [§4.5](../../4-user-surface/4.5-project-identity-and-the-project-s-directory/index.md)): a stable internal handle (`prj_<n>`, never changes, the storage key)
and a display name (the project's directory's base name at creation). Project metadata also holds
the project's directory (`current_root_path`) and project-scoped configuration: convention files loaded into the directives slot ([§3.1](../../3-core-algorithms/3.1-working-set-composition/index.md)), project-specific symbol patterns
and project-scoped stopword additions.

**Open:** whether `conventions_paths` overlaps the instructions slot ([§3.1](../../3-core-algorithms/3.1-working-set-composition/index.md)), which carries the
instruction files opencode loads; decided with the per-slot policies.

**`prj_default`** is reserved for threads created when no project directory was given. It has no
path.
