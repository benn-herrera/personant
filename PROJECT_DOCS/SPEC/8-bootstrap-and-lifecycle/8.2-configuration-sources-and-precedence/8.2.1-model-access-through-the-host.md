#### 8.2.1 Model access through the host

The memory service never calls a model. It requests each judgment it needs — the summarizer's
draft ([§5.2](../../5-model-interaction/5.2-summarizer-prompt-for-closing-summary.md)), the clusterer's grouping ([§5.3](../../5-model-interaction/5.3-clusterer-prompt-for-fallback-clustering.md)), model judgment on surfaced recall candidates ([§3.4](../../3-core-algorithms/3.4-recall-matching/index.md))
and embeddings for recall ([§3.4](../../3-core-algorithms/3.4-recall-matching/index.md)) — from opencode, which runs the model with its own providers and
returns the result. Personant holds no endpoint, provider configuration or API key.

**Open:** A12a — how embeddings are requested through opencode.
