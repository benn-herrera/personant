### 1.8 Memory vetting

Behavior memory text a model will later read is reviewed before it is committed.

- **Reviewer.** A model applying a fixed rubric of the kind used for prompt-engineer review:
  clarity, scope, absolutes that will be over-applied, conflicts with existing entries, and wording
  another model would misread.
- **Behavior memory has one write path.** Every proposed change, whatever proposes it, goes through
  that review. The outcome is recorded with provenance: what proposed it, what the review found,
  and what accepted it.
- **Acceptance is a user-configurable policy** (for example manual acceptance, auto-accept on a
  clean review, or auto-accept everything). Personant ships a default and does not force a policy.
  A pending proposal never blocks a turn and never prompts the user unasked.
- **Direct edits** to the store are not prevented; the versioned store records them.
- **Directive accrual** may propose a behavior-memory change only from patterns aggregated across
  projects, since behavior concerns who does the work, which THESIS.md makes universal. A pattern
  observed in one project stays project-scoped: it may tune that project's conventions or career
  memory, never `directives/user.md` or the defaults. An accrual proposal goes through the same
  review and acceptance path as any other proposal.
- **Career memory** is written every turn and is not reviewed per write. It is protected by
  budgeted slots ([§3.1](../3-core-algorithms/3.1-working-set-composition/index.md)), provenance on every entry, reversibility through the versioned store ([§3.11](../3-core-algorithms/3.11-substrate-commit-cadence/index.md)),
  mechanical checks on write (schema, length, provenance, dedup), and batch content review in the
  consolidation cycle.
- **Standing behavior memory** is re-reviewed periodically, because text that was sound for one
  model can mislead the next.

THESIS.md's rule is a separation of stores: what is learned in a project is written to career
memory. No approval gate, confirmation prompt or other enforcement mechanism is built from it.
