### 5.1 Layout

All of the following sit under `threads/thr_<id>/` and are canonical and tracked:

- **`files.jsonl`:** one line per tracked path, sorted by `path`. Keys are written in this order:
  `{"path","id","size","turn","at","changes":[{"turn","at","from","to","diff","size"}]}`.
  - `path` is the event's path exactly as the producer gave it (the `path` meta of the `fs.*`
    delta). Personant does not normalize it; the (project, path) key compares it byte for byte.
    Supplying project-relative paths is the producer's contract (the sim does; under opencode, the
    plugin).
  - `id` is the 40-hex content id of the bytes of the latest read/write; `size` is their length in
    bytes.
  - `turn` is the owner excerpt number of that event (the thread's turn count after the turn);
    `at` is the excerpt header timestamp.
  - `changes` holds the last ≤ N id transitions, oldest first. `diff` is `true` when the diff was
    kept, `false` when the LCS guard or the write-time threshold skipped it ([§5.2](5.2-write-at-turn-close-applyfileevents.md)).
    A change's `size` is the kept diff's length in bytes, `0` when `diff` is `false`.
  - It is written through `store.WriteJSONL`, which is atomic.
- **`files/<id>`:** the exact current bytes.
- **`files/<from>-<to>.diff`:** a forward unified diff.

Format rationale (CONVENTIONS "Serialization format"):

- The index is flat records, one per line, sorted, so JSONL.
- Blobs and diffs are the raw artifact, so they need no encoding and `diff`/`cat` work on them
  directly.
- Content outside JSONL also avoids `ReadJSONL`'s 1 MiB line cap for large files.
