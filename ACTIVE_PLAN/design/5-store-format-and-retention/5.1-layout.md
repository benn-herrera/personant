### 5.1 Layout

All of the following sit under `threads/thr_<id>/` and are canonical and tracked:

- **`files.jsonl`:** one line per tracked path, sorted by `path`. Keys are written in this order:
  `{"path","id","size","turn","at","changes":[{"turn","at","from","to","diff"}]}`.
  - `id` is the 40-hex content id of the bytes of the latest read/write; `size` is their length in
    bytes (invariant 11 reads it instead of the blob).
  - `turn` is the owner excerpt number of that event; `at` is the excerpt header timestamp.
  - `changes` holds the last ≤ N id transitions, oldest first. `diff:false` means the diff was
    skipped (LCS guard or threshold).
  - It is written through `store.WriteJSONL`, which is atomic.
- **`files/<id>`:** the exact current bytes.
- **`files/<from>-<to>.diff`:** a forward unified diff.

Format rationale (CONVENTIONS "Serialization format"):

- The index is flat records, one per line, sorted, so JSONL.
- Blobs and diffs are the raw artifact, so they need no encoding and `diff`/`cat` work on them
  directly.
- Content outside JSONL also avoids `ReadJSONL`'s 1 MiB line cap for large files.
