### 5.2 Write at turn close (`ApplyFileEvents`)

Events are applied in order. For each event:

1. Compute `id = ContentID(content)`.
2. If the path has no entry yet, create one with empty `changes`. Record no change: a first
   read or write has nothing to diff against. Go to step 4.
3. If `id` differs from the entry's current id, it is a change:
   - read the current blob;
   - compute the diff with `dedup.Diff`. That function applies the two write-time skip rules: the
     LCS guard skips when the line-count product of old and new exceeds `lcsLineProductMax`, and
     the threshold skips when the diff is at or above `dedup.diff-literal-threshold` × the new
     content's size;
   - if the diff is kept, write `files/<from>-<to>.diff`;
   - append the change, recording `diff:<kept>` and its `size`, and trim `changes` to N.
4. Write `files/<id>` if it is absent.
5. Set `id`, `size`, `turn` and `at`.

After the last event, write the index once. A read whose content is unchanged only moves `turn` and
`at`. Commit events never reach the store: they exist only as identifier lines. Write failures stay
non-fatal to the turn, logged as `fs.write-error`, as today.
